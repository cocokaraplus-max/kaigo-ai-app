開発者MENU 操作マニュアル
TASUKARU 管理コンソール
このマニュアルは、運営者向け管理コンソール「開発者MENU」の操作手順をまとめたものです。施設の契約状態・プラン・割引・有効期限など、課金や利用可否に直結する操作を扱います。
アクセス方法 — ブラウザで対象環境の URL の末尾に /dev を付けて開きます（開発者ログインが必要）。
・開発・検証環境：https://tasukaru-dev-(略).run.app/dev
・本番環境：https://tasukaru-(略).run.app/dev
画面は上から順に8つのセクションで構成されています。
セクション1｜ランタイム情報

目的： 現在の稼働状態を確認する（表示専用、操作なし）。

表示内容：

  • Python … アプリ実行環境のバージョン
  • 現在のログイン施設 … いまログイン中の施設コード
  • 登録施設数 … 登録されている施設の総数
  • 現在時刻（JST） … 日本時間の時計（1秒ごとに更新）
セクション2｜環境変数ステータス

目的： アプリ動作に必要な設定値が登録されているかを確認する。

見方： 設定名ごとに ✅（設定済み）／❌（未設定）が並びます。決済など特定機能が動かないときは、まずここで関連する設定が ❌ になっていないか確認します。

注意： この画面は確認専用で、値の変更はできません。修正はサーバー（Cloud Run）側の環境変数設定で行います。

セクション3｜施設一覧

目的： 施設ごとのプラン・契約・割引・有効期限などを操作する（最も使用頻度が高いセクション）。

操作前の確認： 項目が多く表は横に長いため、横スクロールで右側の列を表示します。操作前に施設名・施設コードで対象施設を必ず確認してください。

各列の操作：

  • 施設名／施設コード … 対象施設の識別情報（表示）
  • 状態 … 稼働中／停止のバッジ（表示）
  • プラン … プルダウンで選択。選んだ時点で即時反映
  • 契約 … 月払い／1年／2年／3年などの契約期間（表示）
  • モニター … チェックボックス。チェックした時点で即時反映
  • 割引 … 割引率（なし/20/30/50%）→ 期限（空欄で無期限）→「保存」ボタンの順。保存ボタンを押すまで反映されない
  • 有効期限 … 日付をクリックして YYYY-MM-DD 形式で入力。形式違いはエラー
  • 利用者／スタッフ／記録数 … 各件数（表示）
  • 出納帳 … チェックボックスで施設ごとにON/OFF（確認ダイアログあり）

注意： 割引のみ保存ボタンが必要です。プラン・モニター・出納帳は選択／チェックした時点で反映されます。

セクション3 補足｜プラン・モニター・無料の使い分けとプランバッジ

プランの種類（プルダウン）：

  • スターター／スタンダード／プロ … 有料プラン。上位ほど使える機能が増えます（送迎表・連絡帳＝スタンダード以上、会議記録・タイムカード＝プロ）。
  • 無料（free） … 「まだ有料プラン未契約／最下位」の状態を表すだけです。永久無料を保証する設定ではありません。
  • モニター … 「永久無料・全機能・請求なし」の扱いです。プルダウンで選んでも、右のモニターのチェックボックスをONにしても同じ効果になります。

「モニターのチェックボックス」と「プラン＝無料」の使い分け：

  • 永久に無料で使わせたい施設（自社・提携先など）→ モニターのチェックボックスをONにします。プランは何でも構いません。課金されず全機能が使え、後述のバッジも出ません。
  • プラン＝無料（free） は「未契約・最下位」を表すだけなので、永久無料の手段としては使わないでください。無料期間（有効期限）を未来に設定すると「体験中」扱いになり、バッジが出続けます。

プランバッジ（「スタンダード」「PRO」ラベル）とは：

アプリのメニュー（アプリ一覧）やTOPの打刻ボタンに付く小さなラベルです。その施設のプランに含まれない上位機能に付き、体験中に「これはスタンダード／プロの機能です」と分かるようにするためのものです。

  • 出る条件 … 体験期間中（無料期間が未来）で、かつプランがスターター／スタンダード／プロのとき、上位機能に表示。
  • 出ないケース … ①モニター施設、②プラン＝無料（free）の施設、③体験期間が終わった（＝有料運用中の）施設。有料運用が始まると自動的に消えるので、通常運用の邪魔にはなりません。

アクセス制御（強制ブロック）について： 現状バッジは「表示のみ」で、プラン未満の機能も使えます。プランに応じて実際にブロックする強制制御（enforcement）は既定でオフです。将来オンにする場合は、各施設のプラン値が実態と合っているかを事前に確認する必要があります（切り替えは開発側で対応）。

セクション4｜直近の記録アクティビティ

目的： 最新20件の記録ログ（時刻・施設コード・利用者名・スタッフ名）を確認する（表示専用）。記録が正しく保存されているかの確認に使います。

セクション5｜Claude閲覧許可

目的： Claude に一時的にアプリ画面を見せ、不具合確認や改善提案を受ける。

操作： 「閲覧URLを発行する」を押すと、30分間有効な閲覧URLが生成され、クリップボードにコピーされます。

注意： URL は30分で自動失効します。第三者に渡らないよう取り扱いに注意してください。

セクション6｜開発ツール

目的： 運用補助の各操作。

  • 全セッションクリア … 全スタッフのログインを一斉解除（確認ダイアログあり）
  • 管理者MENUへ … 管理者画面に移動
  • データ再読み込み … 画面を最新状態に更新
  • 施設コードをコピー … ログイン中の施設コードをコピー
セクション7｜AI要約 読み上げ機能（ON/OFF）

目的： AI要約の音声読み上げを施設別にON/OFFする。声の種類・速度は管理者MENUの設定タブで変更します。

セクション8｜ログアウト

「開発者MENUからログアウト」で開発者MENUを終了し、管理者画面に戻ります。

warning運用上の注意
  • 本番環境では課金・利用可否に直結します。操作前に施設コードを必ず確認してください。
  • 割引は「保存」ボタンを押すまで反映されません（他の項目は即時反映）。
  • 環境変数の ❌ はこの画面では修正できません（サーバー側設定が必要）。
  • DEMO001 はテスト用のダミー施設です。本番運用開始前に、テストで設定した契約データ・割引を整理してください。
